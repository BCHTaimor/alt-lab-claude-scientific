# Asking Better Questions Workflow

Use this workflow when a request is broad, ambiguous, internally inconsistent, or missing decisions that would materially affect the answer. Its purpose is to turn an underspecified request into an answerable question before literature review or coding begins.

## Skills

- [Question Quality Assessment](skills/question-quality-assessment.md): Determines whether a request has a clear goal, usable scope, and sufficient constraints to proceed without a consequential guess.
- [Clarification and Normalization](skills/clarification-and-normalization.md): Elicits only high-value missing information and restates the request in a concise, routable form.
- [Examples of Good Questions](skills/example-good-questions.md): Shows the difference between vague and answerable scientific and coding questions, with concrete examples to model.

## Workflow

1. Identify the user's intended outcome.
2. Assess question quality.
3. Ask focused clarification questions when material gaps remain, using at most three clarification rounds and at most three questions per round.
4. Normalize the request into goal, context and scope, constraints, expected output, and selected workflow.
5. Route the clarified request to [Literature Review](../literature-review/overview.md) or [Coding](../coding/overview.md), then proceed without requesting separate permission.

Do not invoke this workflow for a request that already has a clear goal, relevant scope, and usable constraints.
