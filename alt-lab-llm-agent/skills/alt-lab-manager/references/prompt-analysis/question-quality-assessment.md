# Question Quality Assessment

Assess whether the request passes the [Prompt Readiness Rubric](prompt-readiness-rubric.md) before any work begins.

## Sufficient Questions

A question is sufficient when its goal, subject, and expected output are clear enough to proceed without a consequential guess. It does not need to be exhaustively specified.

For literature work, look for a scientific topic or claim and the intended use, depth, audience, or time range when those affect the result.

For coding work, look for the desired change, the relevant system or files when known, and material constraints such as compatibility, tests, or delivery expectations.

## Insufficient Questions

Use clarification when one or more of these are missing or contradictory:

- The actual decision, problem, or learning goal.
- The biological, technical, or project scope.
- The form or depth of the desired output.
- Important constraints, definitions, input data, or success criteria.

Avoid asking for details that would not change the answer. Make a reasonable, visible assumption when the missing detail is low-impact.

## Topic Fragments

A keyword, gene name, assay name, paper title, phenotype, short phrase, or broad command is a topic fragment rather than an answerable request. Examples include `replication origin`, `RAG`, `ATM papers`, `my volcano plot looks wrong`, and `fix the pipeline`.

Do not begin deep research, detailed workflow analysis, code, or tool use for a topic fragment. First clarify the user's goal, relevant context, and expected output. When useful, offer concrete paths such as conceptual explanation, literature review, experiment or data interpretation, workflow planning, troubleshooting, or implementation.
